# NumPy v2 inclusive reader boundary

The actual pinned 9/16 shard at `0a9ae85` completed Build and Test for the `read_header` mutation from `>` to `>=` and missed the mutation. The public reader bounds its declared dictionary at 65,536 bytes. After that check it reads the declared bytes, validates the dictionary and decodes the enclosed payload. The original implementation has used this inclusive scanner limit since `a016fd2`. It does not require the writer's aligned payload offset.

The new public decode regression covers 65,524 bytes with an aligned v2 payload, the exact 65,536-byte reader limit, and a complete file one byte beyond the limit. The two accepted cases retain their native RGB16 type and dimensions, with all three expected normalized f32 bit patterns. The exact-limit fixture uses the declared offset and space padding before the dictionary newline. Its payload offset is 12 modulo 64. The independent NumPy 2.5.4 reader with pickling disabled and an explicit 65,536-byte metadata limit accepts the same two fixtures with exact unsigned codes and rejects the larger file. This evidence covers the existing reader behavior. The earlier P2 writer-aligned fixtures retain their separate role. [P2 metadata evidence](../../p2-npy-evidence/README.md).

The original patch was recovered directly from the typed mutation list and verified against the canonical saved diff. It compiled and failed at exactly 65,536 bytes. The original decoder source was then restored byte for byte. The same focused test passed, followed by all four tests in `cpu_npy`. Formatting and the reviewed Miri-source manifest validated.
